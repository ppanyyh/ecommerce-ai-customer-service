# RESUME_PROJECT_TEXT.md — 简历材料

## 一行项目标题

**电商客服AI助手（Python/FastAPI/混合RAG）：检索+风险控制+结构化订单+本地降级的全链路原型，配一次性盲测验收纪律**

## 50字版本

基于 FastAPI + Chroma + DeepSeek 的电商售后客服原型：混合检索、结构化订单直查、风险下限与转人工机制、LLM 不可用本地降级；80 条一次性盲测全链路归档。

## 100字版本

独立完成的电商售后客服 AI 后端原型（Python/FastAPI/ChromaDB/bge-small-zh/DeepSeek）。实现关键词+向量 RRF 混合检索、12 位订单号结构化直查（不入向量库防串单）、8 条风险规则下限机制（模型不可降低风险等级、高风险自动转人工）与 DeepSeek 失效本地降级。建立"候选冻结→盲测一次性执行→哈希留痕"评测纪律，80 条最终盲测完整归档（内部泄漏 0、P95 42.4ms，未达标指标如实披露）。

## 三条项目要点（精简版）

1. 设计并实现混合检索（关键词 RRF K=60 + bge 向量）与结构化订单路由，解决"规则类语义召回弱"与"向量检索串单"两类问题；
2. 构建 8 条风险规则的下限机制：统一等级定义、否定承诺守卫、模型结果只能抬高不能降低风险、高风险强制转人工；
3. 建立一次性盲测验收流程（1250 条历史查询黑名单查重、24 项自动校验、`--execute-once` 门控），80 条盲测一次执行完整归档。

## 五条项目要点（详细版）

1. **混合检索**：关键词（别名/型号/数字增强）+ 向量（bge-small-zh，512 维）RRF 融合；规则片段 index/display 拆分，规则原文不进用户答案；
2. **结构化订单**：12 位订单号精确路由，不经过向量库；不存在/不完整/高风险组合分层处理，不编造送达与退款时间；
3. **风险机制**：8 条规则（HR-01~08）等级唯一定义于 `risk_levels.py`；结构化意图检测 + 否定守卫 + 风险下限（模型只能抬高）；转人工按风险类型输出文案且不暴露内部编号；
4. **可用性**：DeepSeek 未配置/失败时本地模板组稿，零泄漏、安全约束同等生效（最终盲测即以 DeepSeek 0 次调用完成全部 80 条）；
5. **评测纪律**：开发集→validation→候选 SHA 冻结→80 条盲测（先冻结 16 项目标）→唯一一次执行→结果归档；工程与安全指标全达标（泄漏 0/违规 0/P95 42.4ms），检索未达标指标（Hit@1 54.5%）如实披露并归档失败模式清单。

## 技术栈

Python 3.12 · FastAPI · Uvicorn · Pydantic v2 · ChromaDB · sentence-transformers（BAAI/bge-small-zh-v1.5）· RRF 混合排序 · DeepSeek API（OpenAI 兼容）· 原生 HTML/CSS/JS · SHA-256 冻结清单 · 自研评测器（一次性执行门控）

## 可使用的真实指标（均已归档，可引用）

- 最终盲测 80/80 一次执行、0 异常 0 重试、哈希前后一致
- 内部术语泄漏 0；禁止承诺违规 0；DeepSeek 真实调用 0
- irrelevant 误放行 0%；wrong handoff 8.8%（目标 ≤10%）
- 商品 Hit@1 87.5%；FAQ Hit@1 90%；scope 准确率 94.3%
- 预热后 P95 42.4ms（目标 <100ms）
- 开发集阶段 Answer Hit@1 90.2%、validation 24/24（含 4 轮无回归）

## 不应声称的内容（诚实边界）

- ❌ 不可声称"生产级/上线系统"——`production_ready=false`，模拟数据、无鉴权、CORS 全开；
- ❌ 不可声称"检索准确率 90%"——那是开发集数字，盲测 Hit@1 为 54.5%；
- ❌ 不可声称"通过了最终盲测"——16 项目标达标 6 项，9 项未达标已归档；
- ❌ 不可声称全部代码独立手写——AI 辅助开发，人的价值在架构决策与验收纪律；
- ❌ 不可声称支持多轮对话/真实订单——均未实现。
