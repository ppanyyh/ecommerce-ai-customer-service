## 二、修改规则（对应诊断根因）

1. **通用弱词降权**（治理 H-025/H-021）：`商品/购物/问题/怎么样/质量/订单/处理`
   命中业务关键词时按弱词计分（累计上限 0.5），不能单独构成高置信命中。
2. **多通道封顶**（治理 H-025 双通道 7.9 分）：同一词通过"业务关键词/属性词"命中只按
   最高通道计一次；已被明确匹配短语覆盖的汉字不再重复计入汉字重合。
3. **汉字重合降为弱辅助**（治理 H-004）：0.15/字、上限 0.8，低于任何明确业务词
   （最小为单字关键词 1.0）；无明确业务证据时弱证据整体上限 0.8。
4. **实体保护**：完整商品编号 → 强制 Top-1（同 v1）；名称/别名/扩展同义词命中 →
   PRODUCT 片段 rrf_score + ALIAS_BOOST(0.0002)。
5. **epsilon 并列裁决**（治理 H-007 对称并列）：分差 < EPSILON(0.0003) 视为并列。
   裁决顺序：中性属性询问且实体片段同时是关键词 Top-1 → 实体优先；
   担忧/风险疑问式（会不会/没(什么)事吧/不管用等，analyzer has_concern_scenario）
   → 优先 FAQ/规则等解答型内容；其余按 vector_similarity 高者优先，再按 chunk_id。
6. **风险规则保留位**（治理 H-021/H-022 rule_miss）：analyzer 识别出具体风险意图且
   必需规则在候选 Top-10 中时，最终 Top-3 = 1 个内容片段 + 必需规则（最多 2 条）+
   综合分最高者；规则不在候选时记录 rule_candidate_missing，不凭空创建；
   泛化词不触发保留位。
7. **业务范围门控**（治理 H-025）：无商品实体 + 仅泛化质量咨询 + 无具体售后/风险意图
   → `{"supported": false, "reason": "缺少可识别商品或具体售后事实", "results": []}`。
   这是业务范围判定，不是相似度拒答阈值；未设置任何向量阈值。

## 八、迭代过程（如实记录）

评测共运行 4 轮（EPSILON=0.0003、ALIAS_BOOST=0.0002、弱词/汉字重合参数全程未变，
仅修正实现层缺陷，均非阈值调参）：

2. 第 2 轮：改为"实体+关键词双第一优先"→ H-002 修复，但 H-006（戴着耳机冲淋浴，
   担忧式问题）被同一规则误推商品为 Top-1；
3. 第 3 轮：引入通用"担忧/风险疑问式 vs 中性属性询问"判别（has_concern_scenario）→
   H-002/H-006/H-007 三类别名问题全部正确，但 H-006 的"没(什么)事吧"模式漏匹配；
4. 第 4 轮：补全模式 `没(什么)?(事|问题|影响)(吧|吗)` → 全部 8 项成功条件通过。

## 九、回归风险

- epsilon 裁决中的"担忧式→FAQ 优先"依赖 analyzer 的担忧模式词表覆盖；未覆盖的
  担忧表述会退回 vector_similarity 裁决（与 v1 行为一致，不会更差）；
- 风险规则保留位只在 analyzer 识别出具体风险意图时生效；analyzer 漏识别的意图
  （如新的缺陷说法）不会触发保留位，但也只是退回 v1 行为；
- 弱词表（商品/购物/问题/怎么样/质量/订单/处理）为封闭集合，若业务关键词未来新增
  同类泛化词，需要同步维护；
- validation_set_v1 已参与本轮调试，24/24 的结果不能作为泛化结论——**必须用全新
  final blind set 复核**（见下）；
- H-026~H-030（折扣/仓库/无关问题）不属于门控范围，v2 仍会返回检索结果但无
  高置信错误命中标记（错误命中 0/6）。
