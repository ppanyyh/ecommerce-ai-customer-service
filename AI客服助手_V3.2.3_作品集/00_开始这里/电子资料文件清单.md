## 二、建议补充但当前尚未制作

这些材料不会阻碍简历投递，但补齐后展示效果更好：

- 2～3 分钟演示视频：启动服务、健康检查、商品问答、订单查询、高风险转人工、停止服务。
- 4～6 张干净截图：主页、普通问答、订单查询、高风险案例、健康检查、架构图。
- Git 仓库：整理后提交代码，补充许可证，并确认没有 `.env`、Token、个人数据、模型缓存和临时日志。
- 在线演示地址：只有部署稳定且不暴露密钥时再提供；当前本地演示已足够用于面试。
- 一页 PDF 项目介绍：可由 `PORTFOLIO.md` 精简转换，方便招聘方快速浏览。

## 三、投递组合

### 最小投递包

1. 一页简历；
2. Git 仓库或作品集链接；
3. `PORTFOLIO.md` 转出的 PDF。

### 技术面展示包

在最小投递包基础上增加：

1. 本地演示；
2. final blind 原始报告；
3. V3.2.3 热修复说明；
4. 关键源码讲解。

## 四、不应发送或提交的文件

- `.env`、API Key、Hugging Face Token 和任何账号凭证；
- `.venv`、Chroma 本地数据库、模型缓存、`__pycache__`；
- `err*.txt`、临时 PID、`holder.ps1`、系统临时目录文件；
- 包含真实客户、订单、手机号、地址或公司内部数据的材料；
- 未经整理的大量历史调试脚本和重复报告。

## 五、发布前最终检查

- [ ] 简历写“个人主导、AI 辅助完成”。
- [ ] 明确 V3.2.2 的盲测指标不属于 V3.2.3。
- [ ] 明确项目是作品集原型，`production_ready=false`。
- [ ] 能独立启动、演示、停止服务并解释失败案例。
- [ ] 仓库和压缩包中没有密钥、个人数据、虚拟环境与缓存。
- [ ] 所有截图和视频使用模拟数据。
