## 1. 触发问题

用户实测问题：

> "昨天刚收到的耳机，今天早上右边就不出声了"

错误行为：分类为「商品」、风险「低」、不转人工、返回耳机售价与包装内容——而这是明确的已购质量缺陷，应触发 HR-08（风险=高、转人工）。

## 2. 根因

`risk_intents.py` 中功能失效正则的单边分支为：

```
(左|右|一边|另一边)(耳|边)?不(响|出声)
```

该模式要求**方位词与失效词紧邻**（中间最多隔一个"耳/边"字）。本句中方位词「右边」与失效词「不出声」被连接词「就」隔断，整体漏判；同时泛化模式 `没(有)?声(音)?了?` 只覆盖"没（有）声（音）"，不覆盖「不出声」。

## 3. 最小修复

按指令做成**独立、可测试的小函数**（未继续扩大大正则）：

- `detect_single_side_audio_loss(q)`：新检测函数，挂入 `detect_defect` 售前守卫之后；
- 方位/对象：左耳/右耳/左声道/右声道/左边/右边/一边/另一边/另一只/另一个/单边/单耳/一只/一个耳朵等；
- 失效状态：没（有）声（音）/不出声/不响/无声/失声/声音没了/不发声；
- 自然连接词：就/突然/完全/现在/开始/已经/怎么/又/后来等（以字符白名单实现，间隔 ≤8 字，非"就"字特例硬编码）；
- 附加两类结构模式：不对称表达（只有一边有声/一只响另一只不响）与状态变化表达（开始时有声音，后来不出声了）；
- 专项售前守卫：会不会没声/容易没声/单耳模式/声道/音量/降噪/佩戴等咨询不触发；
- 已发生功能失效直接判定质量缺陷；售前担忧与参数咨询不触发；
- **未修改其他风险规则、RRF、向量阈值、门控或知识库**。

改动文件：`backend/risk_intents.py`（新增专项检测）、`backend/main.py`（仅版本标识 3.2.2→3.2.3 与 title）。
