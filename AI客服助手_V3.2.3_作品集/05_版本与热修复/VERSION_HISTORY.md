# VERSION_HISTORY.md — 版本历程

> 不做流水账，只记录每个版本解决的**核心问题**与留下的关键决策。

## V1 — 本地规则原型（05_AI_Demo）

**核心问题：验证业务口径。** 纯 HTML/CSS/JS 关键词匹配版（商品/FAQ/SOP/模拟订单），确立沿用至今的基础设定：5 类问题分类、风险是独立维度（不是分类）、六要素回复结构、哪些场景必须转人工。双击即运行，DeepSeek 零依赖——后来成为 V2+ 的降级兜底。

## V2 — DeepSeek 与 API 集成（08_V2_DeepSeek）

**核心问题：LLM 接入的边界与可用性。** FastAPI 后端 + DeepSeek 生成 + 本地规则兜底；确立"双层输出"原则（answer 只面向消费者，规则编号/依据只进内部字段）与后端泄漏检查→重试→安全模板的三步防线。**关键取舍：DeepSeek 失败时前端自动回退本地规则引擎**——"服务永远可用"从此成为架构约束而非补丁。

## V3 — 向量检索（09_V3_Vector_RAG）

**核心问题：纯关键词的语义召回缺口。** 引入 Chroma + bge-small-zh-v1.5。纯向量基线评测暴露结构性短板：**规则类 Hit@1=0%**（FAQ 语义竞争），Recall@3 94.1% 说明正确片段在 Top3 内——这直接催生了 V3.2 的混合检索与"规则片段 index/display 拆分"设计。**关键决策：订单不进向量库**（防串单/防隐私召回/保事实性）。

## V3.1 — 门控与独立盲测（同目录重构）

**核心问题：无关问题误命中 + 评测污染。** 引入门控三分类（supported/unsupported_business/irrelevant）与 query_analyzer 意图识别；同时确立评测纪律基线：baseline 先行、代码冻结后测、**独立盲测集一次性执行**（首个盲测暴露开发集→盲测的泛化落差：Hit@1 76.7%、不可回答误命中 100%）——"门控只认显式意图模式"被证明是过拟合源头。

## V3.2 — 风险泛化与本地降级

**核心问题：风险意图的确定性召回 + 服务连续性。** 结构化风险意图检测器（risk_intents，七类小函数）、业务感知混合检索 v2（epsilon 并列裁决/保留位/安全网）、`compose_local_answer` 本地降级组稿（零泄漏）。期间修复关键 bug：规则 ID 前缀不匹配导致风险 handoff 全失效。盲测 v2 复测仍显示泛化落差——**确立了"只报告不修复"的盲测纪律**。

## V3.2.1 — 落地前修复（同目录）

**核心问题：服务实测暴露的六类业务缺陷。** 未知商品结构化识别、复合价格意图（回收/以旧换新不再误判售价）、承诺否定守卫、订单本地结构化回答、分风险类型转人工文案、纯配送时效承诺口径调和。补充开发集 80 条 + 全量回归零新增。**教训记录**：曾把 9 条 HR-07 用例风险为"中"误判为"分级口径"，实际是系统性缺陷（见 V3.2.2）。

## V3.2.2 — 统一风险等级与最终冻结（同目录）

**核心问题：风险等级被系统性降低的双层根因。** ① 适配器 `_RISK_ORDER` 数组反序（高/中/低），多风险候选取了最低风险；② `_risk_floor` 只传 handoff 不传规则等级。修复：新建 `risk_levels.py` 唯一定义，全链路统一调用，`risk_floor_level` 贯穿检索→兜底。版本标识升 3.2.2，候选 17 文件冻结。

## 最终盲测与停止（final blind set v3）

**核心问题：泛化能力的诚实度量。** 80 条全新盲测（1250 条历史查询黑名单查重、24 项自动校验、28 条人工抽查、16 项目标先于结果冻结），`--execute-once` 门控下唯一一次执行。结果：**工程与安全面 9 项全达标**（泄漏 0/违规 0/DeepSeek 0/P95 42.4ms），**检索面 9 项未达标**（Hit@1 54.5%、unsupported 误放行 20% 等），失败模式 7 类全部归档。

## 最终停止原因

**按既定纪律主动停止，而非能力耗尽。** 盲测只执行一次是事先冻结的规则——若继续"修复→重跑"，盲测即退化为开发集，整个评测体系失去意义。选择：如实归档全部结果（`project_status=portfolio_prototype_completed`、`production_ready=false`），失败清单作为后续版本需求输入，项目转入作品集整理阶段。这个"在最好看的指标和最诚实的记录之间选后者"的决策，是本项目最重要的产出之一。
